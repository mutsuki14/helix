# Helix · 执行（Build）

> 前置：已有 Seed（L2）或迷你 Seed（L1）。修 bug 可从任何级别直接跳到本手册的"系统化调试"节。
> 深读文件（按需加载）：`methods/plan.md` 计划编写与分批执行 · `methods/tdd.md` strict 协议与测试反模式 · `methods/debugging.md` 深度调试 · `methods/subagents.md` 派发提示词与两阶段评审 · `methods/git.md` worktree 与收尾提交。全部位于本技能目录的 `methods/` 下，直接读文件。

**先判断要不要计划文档**：跨会话 / 需用户审批分批走 / 要派多个实现子代理 → 先读 `methods/plan.md` 写计划再动工；否则 Seed 的 AC 清单就是计划，直接开工。

## 基线优先（源自 Aegis）

写第一行代码之前，先对齐项目的**真实基线**，减少猜测和返工：

1. **定位 owner**：这个行为现在归哪个文件/模块管？改动应该落在 owner 处，不另起炉灶。
2. **读契约**：受影响的接口、类型、schema、事件格式——读实际定义，不凭记忆。
3. **摸惯例**：命名、错误处理、测试组织方式，看 2–3 个同类先例，让新代码长得像老代码。
4. **最小读集**：只读与本任务相关的最小文件集合；范围大、不确定去哪找时派一个只读探索子代理（Explore 类），拿结论不拿文件堆。

**改动必要性（Change Necessity）**：每处源码修改都要说得出"为什么必须改这里"。说不出的修改就是范围蔓延——删掉或记入 `later`。

## TDD 路由

TDD 默认**关闭**，按信号路由（融合 Aegis 的路由开关与 Superpowers 的测试纪律）：

| 信号 | 路由 |
|---|---|
| 用户显式要求 strict / test-first | **严格 TDD**：红 → 绿 → 重构，测试先行，一次一个行为 |
| AC 可测试化 且 宿主项目已有测试设施 | **建议 test-first**：先为本次 AC 写失败测试再实现；向用户提一句即可，不强推 |
| AC 难以自动化（UI 观感、探索性工作） | 跳过 TDD，验证走 `verify` 的手动证据路径 |

测试红线：**禁止为了让测试通过而弱化测试**（放宽断言、mock 掉被测逻辑、删除失败用例）。测试挂了只有两个合法出路：修实现，或证明测试本身错了并说明依据。
进入 strict 模式或要写/改测试时读 `methods/tdd.md`（红绿重构协议 + 六大测试反模式）。

## 系统化调试（源自 Aegis，bug 必经之路）

遇到 bug、测试失败、回归、意外行为——**先根因，后修复**。禁止"先改了再看"：

1. **复现**：拿到确定性的复现步骤/最小用例。复现不了就先构造观测（日志、断点、二分输入），不许盲改。
2. **定位**：沿调用链向根因追溯，问"这个错误值从哪来"直到源头。症状处的修补（在出错点加判空、try/catch）不是修复。
3. **声明根因**：一句话写出"根因是 X，证据是 Y"。证据必须是观测到的事实（日志行、变量值、diff），不是推理。
4. **最小修复**：在根因处做最小改动。修复引入的每个新分支/回退路径都要有存在理由。
5. **回归验证**：原复现步骤转绿 + 相邻场景不被打破。这一步的证据留给 `verify` 用。

复现困难、根因链条长、flaky、或两次修复失败 → 读 `methods/debugging.md`（根因追溯、二分定位、条件等待、二击规则），不要第三次盲试。

## 子代理派发纪律

并行只用于**真正独立**的任务（无共享状态、无先后依赖）。派发时传**上下文包**，不贴全量对话：

```text
SubagentPacket:
- 任务 / 目标 / 停止条件
- 相关文件（路径 + 行号提示）
- 已知事实（已验证的，别让子代理重新推导）
- 非目标 / 不许动的东西
- 期望产出格式 + 期望的验证动作
```

子代理的报告是**证据候选**，关键结论仍要抽查最小原始片段核实。
实现者提示词模板、两阶段评审（规格符合度→代码质量）、并行回收规则读 `methods/subagents.md`；人格立场段取自 `methods/personas.md`。分支/worktree/收尾提交纪律读 `methods/git.md`。

## 执行期漂移自查

- 每完成一条 AC，对照 Seed 勾掉，并瞄一眼 Non-goals——刚做的事有没有越界。
- 冒出的新想法/顺手优化 → 记 `later`，不做。
- 发现 Seed 本身错了（假设被证伪、约束冲突）→ 停止执行，回 `clarify` 走 reseed，不带病续跑。
- L2 多圈任务每圈结束追加 journal（格式见 `evolve` 手册）。

执行完毕（自认为所有 AC 已满足）→ 读 `methods/verify.md`，未经验证不得宣称完成。
