# Helix · 验证（Verify）

> 触发：即将宣称"完成/修好/通过/可以合并"，或即将 commit、PR、发布、交接。
> 铁律（源自 Aegis）：**先验证，后宣称**。证据不足就降级说法，绝不先说完成再补验证。

## 三级评估门（源自 Ouroboros，零成本化改造）

Ouroboros 用"机械 → 语义 → 多模型共识"三段门控制评估成本。Helix 保留分级思想，把"多模型"改成**同宿主多视角子代理**，因此不需要任何额外 LLM 配置：

### Gate 1 · 机械门（成本 $0，所有级别必过）

- 跑项目自己的客观检查：build / typecheck / lint / 测试套件 / 格式化。
- **读完整输出**，不是只看退出码——警告、跳过的用例、慢化的步骤都是信号。
- 证据必须**新鲜**：本轮改动之后跑出来的才算；改动前的绿灯不能复用。
- 任何一项红 → 不进下一门，回 `build`（bug 走系统化调试）。
- 本技能的脚本可代跑并汇总：`node scripts/gate.mjs '{ mode: "evidence", commands: [{ cmd: "npm test", scope: "target" }, { cmd: "npm run lint", scope: "other" }] }'`，输出可直接喂给 receipt 定级。

### Gate 2 · 语义门（L1 及以上）

逐条 AC 对照证据自评：

```text
AC1: pass | partial | fail — 证据: <跑了什么 / 看到什么>
AC2: ...
```

- 每条 AC 用它在 Seed 里登记的验证方式来验，不许临场换成更宽松的标准。
- `partial` 和 `fail` 必须写清缺口；全部 `pass` 才进下一门（L1 到此为止，可出收据）。

### Gate 3 · 共识门（仅 L2 高风险：契约变更 / 跨模块 / 数据迁移 / 安全面）

派 2–3 个**互不通气**的子代理独立评审，人格与立场段取自 `methods/personas.md`（默认组合：反对者 + 黑客 + 简化者），评审员完整提示词模板见 `methods/review.md`。按努力度阶梯配给：默认 2 人格，契约/数据/安全面 3 人格；上一圈共识门失败过则加一。改动命中特定领域（迁移/并发/安全/性能/前端）时，按 `methods/domains.md` 的触发映射追加对应专家人格（至多 2 个）。

裁决：某项质疑被多数人格确认 → 按 fail 处理回 `build`；只有一票且证据不实 → 记入残余风险。视角多样性比人数重要——三个相同提示词的副本不算共识。**critical/major 发现出现相反结论、或你想否决一个 critical 时，不投票——走 `methods/review.md` 的辩论式裁决**（起诉→反驳→互驳→裁决/转实验）。
宿主无子代理设施时按 `methods/personas.md` 的串行自演回退协议执行（从严裁决：单一 critical 即阻塞）。

## 漂移度量（源自 Ouroboros，量表化）

出收据前自评一次漂移分，防"活干完了但不是当初要的活"：

| 维度 | 权重 | drift = 0 的标准 |
|---|---|---|
| 目标 Goal | 0.5 | 交付物就是 Seed Goal 描述的东西 |
| 约束 Constraints | 0.3 | 所有 Constraints 仍被遵守，Non-goals 未被触碰 |
| 本体 Ontology | 0.2 | 实体/状态/生命周期与 Seed Ontology 一致，没偷偷加状态 |

```
Drift = Σ(drift_i × weight_i)      门槛：≤ 0.3
```

每维分数写一行依据，然后用随包脚本做确定性计算（不要心算）：
`node scripts/gate.mjs '{ mode: "drift", goal: 0.1, constraints: 0, ontology: 0.2 }'`（脚本在本技能目录下；无 node 时按公式/规则手算，并把每一步写在回复里）
**Drift > 0.3 → 停止宣称**，二选一：回 `clarify` 走 reseed（需求确实变了，让用户裁定），或回滚越界部分。

## 证据收据（源自 Aegis，简化版）

三门全过后出收据。L0 允许一句话（"跑了 X，结果 Y，未覆盖 Z"）；L1/L2 用结构：

```text
Helix 收据:
- 检查动作: <跑了什么门、什么命令>
- 结果: <关键输出/退出状态>
- 覆盖范围: <证据实际覆盖的面>
- 未覆盖: <没验到的面——诚实列出>
- 残余风险: <已知但接受的风险>
- 漂移: <分数 + 一句依据>
- 置信: A | B | C
- 下一个最有价值的验证: <如果用户想更放心，该跑什么>
```

置信分级**由工具确定性判定，不许手定等级**——你只提供原始事实（跑了什么、退出码、是否新鲜、覆盖域、未覆盖面）：

`node scripts/gate.mjs '{ mode: "receipt", checks: [{ name: "npm test", exit_code: 0, fresh: true, scope: "target" }, { name: "npm run lint", exit_code: 0, fresh: true, scope: "other" }], uncovered: ["未验证并发场景"] }'`（脚本在本技能目录下；无 node 时按公式/规则手算，并把每一步写在回复里）

判定规则（工具内置）：

- **A**：全部通过且新鲜 + 有 target 证据 + 有 regression 证据 + 无已知未覆盖面。
- **B**：全部通过且新鲜 + 有 target 证据，但缺回归证据或存在已列出的未覆盖面。
- **C**：任一检查失败/不新鲜，或没有直接针对目标的证据。**置信 C 不得宣称"完成"**——改说"实现了 X，尚未验证 Y"。
- 谎报 `fresh` 或漏报 `uncovered` 等于骗过自己的门——原始事实必须与对话中贴出的输出一致。

## 完成边界

- 单个切片/单圈的完成 ≠ 整个需求被满足；宣称只能覆盖新鲜证据所及的范围。
- 停止状态只有四种：`done`（成功证据齐）/ `blocked`（缺依赖或信息，写明缺什么）/ `needs-verification`（实现在、证据不够）/ `scope-exceeded`（继续就越界，交还用户）。
- 破坏性/不可逆动作（删数据、强推、发布）需要**针对性授权**，笼统同意不算数。
- 忠实汇报：测试挂了就说挂了并贴关键输出；跳过的步骤明说跳过。
- 人工代码评审的请求与接收纪律（含评审员提示词、critical 阻塞规则）读 `methods/review.md`。

未全过（有 fail/partial、共识门被推翻、漂移超标）→ 不是失败，是环的下一圈：读 `methods/evolve.md`。
