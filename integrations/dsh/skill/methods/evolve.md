# Helix · 进化与续航（Evolve）

> 触发：验证未全过要进下一圈；任务卡住（`helix unstuck`）；长任务跨会话；要记架构决策（`helix adr`）；查状态（`helix status`）。

## 进化循环（源自 Ouroboros：评估输出 = 下一圈输入）

验证未全过时，不是"再试一次"，而是先做**失败分析**，让下一圈站在这一圈的尸体上：

```text
圈 N 失败分析:
- 挂掉的门/AC: <哪条、现象>
- 根因假设: <为什么挂——带证据>
- 本圈新知识: <这圈学到的、下圈不必重推的事实>
- 下圈改法: <具体改什么，与上圈有何不同>
```

**上升法则**：每一圈必须满足其一——多通过至少一条 AC，或产生记入账本的新知识（如"方案 A 被证伪，因为 X"）。

**循环裁决用工具算，不靠感觉**。每圈评估后调用：
`node scripts/gate.mjs '{ mode: "loop", ac_total: 6, ac_passed_history: [2, 4, 4], repeated_same_error: false, oscillation: false }'`（脚本在本技能目录下；无 node 时按上方公式手算，并把每一步算式写在回复里）
返回四种裁决：`converged`（全过，走漂移门+反熵清退后收据离场）/ `continue`（有上升，写失败分析进下一圈）/ `unstuck`（停滞，先脱困）/ `cap-reached`（到硬上限）。

**硬圈数上限：同一 Seed 默认 5 圈。** 到限即停，向用户汇报：已通过/未通过的 AC、每圈失败分析摘要、三个选项（缩小范围 reseed / 接受部分完成 / 换根本方案）。上限防无限空转——这是 Ouroboros 硬代数上限在 Agent 场景的等价物。

## 停滞检测（四种模式，源自 Ouroboros resilience）

打转与震荡由你观察后作为标志传给 loop 裁决；无漂移运动（AC 通过数不涨）与收益递减（按当前每圈速度在剩余圈数内无法收敛的投影）由工具从 AC 历史**自动判出**：

| 模式 | 症状 |
|---|---|
| **打转 spinning** | 同一错误/同一失败用例连续 ≥2 圈出现，改法本质相同 |
| **震荡 oscillation** | 修 A 坏 B，修 B 又坏 A；diff 在两个状态间来回 |
| **无漂移运动 motion-without-progress** | 编辑量很大，但 AC 通过数不变 |
| **收益递减 diminishing-returns** | 每圈修复的东西越来越小，但残余问题不收敛 |

## 五视角脱困（Ouroboros 横向思维人格的零配置版）

停滞确认后，**停止编码**，用五个视角各写一句话诊断（可并行派子代理，也可自己逐一切换立场），然后选最有希望的一条执行：

1. **简化者**：砍掉一半需求还成立吗？最小可行版本长什么样？
2. **黑客**：有没有"不优雅但正确"的捷径？（换库、降级方案、预计算）
3. **反对者**：这个方向是不是根本就错了？被放弃的方案里有没有该捡回来的？
4. **架构师**：问题是不是出在结构而非代码？（职责放错模块、抽象层缺失）
5. **研究者**：缺的是不是信息而非努力？（该读文档/源码/issue 而不是继续试）

选定路径后写入失败分析的"下圈改法"，按新路径进圈。脱困后仍打转 → 触发圈数上限逻辑，交还用户。

## 长任务续航（源自 Aegis）

L2 多圈任务、上下文将被压缩、或需要跨会话时，把状态外置到账本，**恢复时先读账本，不重推**：

`.helix/journal.md`（append-only，只追加不改写历史）：

```markdown
## 圈 N — <日期> — <一句话本圈目标>
- AC 状态: AC1 ✔ / AC2 ✘ / AC3 ◐
- 已验证事实: <本圈确认的，下圈直接信>
- 失败分析: <如上格式，或"本圈通过">
- later: <范围外想法，谁都不许顺手做>
- 下一步: <具体到第一个动作>
```

恢复流程（新会话 / 压缩后 / `helix status`）：读 `.helix/seed.md` + journal 最后一圈 → 核对工作区实际状态与账本是否一致（git status、关键文件）→ 从"下一步"继续。不一致以工作区实况为准并追加更正记录。

## 架构决策记录（ADR）

改变架构/契约/技术选型的决定，记入 `.helix/decisions.md`（项目已有 ADR 目录则记到项目的，不另立）：

```markdown
## ADR-N: <决定> — <日期>
- 背景: 为什么需要决定
- 决定: 选了什么
- 放弃项: 放弃了什么、为什么
- 重审触发器: 什么情况下这个决定应被重新审视
```

## 反熵清退（源自 Aegis anti-entropy）

环收敛离场前的最后一扫，防"幽灵代码"堆积：

- 本任务引入的每个 fallback / 兼容层 / 特判分支：要么已随任务结束删除，要么带着**退役触发器**记录在案（"X 上线后删除本回退"）。
- 替换旧逻辑时：旧路径要么删除，要么写明保留理由 + 退役条件。没有理由的双轨并存不许留下。
- 临时调试代码、注释掉的旧实现、一次性脚本：离场前清除。

清退完成 → 出最终收据（`verify` 手册格式），环正式结束。

## 复盘（外环）

L2 多圈任务收据发出后做一次复盘，把这次的教训变成下个任务的起点：读 `methods/retro.md`（复盘四问 + `.helix/learnings.md` 学习账本 + 入账门槛）。单圈顺利收敛的可跳过；代价高昂的失败必须做。
