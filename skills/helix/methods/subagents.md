# Helix · 子代理派发（含现成提示词）

> 触发：并行探索、派发实现者、两阶段评审。派发原则见 `methods/build.md`；本文给现成模板。

## 通用规则

- 只并行**真正独立**的任务；有共享文件/先后依赖的串行。
- 坐标员（你）是 **git 变更的唯一所有者**：子代理不 commit、不建分支、不动 worktree。
- 子代理报告是证据候选：关键结论抽查最小原始片段。
- 探索类用只读子代理；实现类才给写权限。

## 实现者提示词模板

```text
你实现 Task N: <名字>。

## 任务全文
<把计划里该 Task 的全文贴进来——不要让子代理自己去读计划文件>

## 上下文包
任务/目标/停止条件: ...
相关文件: <路径:行号提示>
已知事实: <已验证的，直接信>
非目标: <不许动的>
期望产出: <文件与形态>
期望验证: <跑什么命令证明完成>

包是地图不是证据：动手前用最小代价核实关键事实。

## 规则
- 开工前有疑问先问，不猜；
- 只实现本 Task 声明的范围，冒出的范围外想法记入报告的 later 区；
- 写完跑你声明的验证命令，把完整输出贴进报告；
- 不 commit、不动分支；把改动留在工作区给评审；
- 报告格式：做了什么 / 验证输出 / 没做什么与原因 / later / 自评风险。
```

## 两阶段评审（源自 Superpowers/Aegis，实现后必走）

**阶段 1 · 规格符合度**（评估者人格）：只回答"实现 = 任务说的东西吗"——
多做了什么（范围蔓延）、少做了什么（漏项）、改了不该改的（越界）。逐条对照任务全文与 diff，不评代码风格。

**阶段 2 · 代码质量**（架构师+黑客人格，规格过了才进）：

```text
你评审这份 diff 的生产就绪度，结论先行，找不到问题就明说并列出未覆盖面。
按序检查：
1. 正确性: 边界/空值/异常路径/并发；构造能出错的具体输入；
2. 归属: 改动落在正确的 owner 吗？有没有本该改源头却在调用方打补丁；
3. 复杂度: 新增分支/兜底/适配层各自的存在理由；能删的指出来；
4. 一致性: 命名/错误处理/测试组织是否跟随项目惯例；
5. 测试: 反模式扫一遍（测 mock、弱断言、睡眠等待、污染）。
每条发现给 位置 + 严重度(critical/major/minor) + 建议。critical 阻塞合并。
```

评审发现的处理见 `methods/review.md` 的"接收评审"节。

## 并行派发的回收

- 派发时就写好每个子代理的**验收标准**（期望产出+验证），回收时逐个对照；
- 有失败的不整批重派：只重派失败者，成功结果保留；
- 回收后做一次**冲突扫描**：多个子代理改了相邻代码时，跑全量 Gate 1 确认合成状态成立。
