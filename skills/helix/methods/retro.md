# Helix · 复盘与学习环（Retro）

> 触发：`helix retro`；环收敛退出后（L2 多圈任务默认做，单圈可跳过）；一次代价高昂的失败之后。
> 这是 Helix 的外环：内环（进化循环）让**这个任务**收敛，外环让**下个任务**起点更高。Ouroboros 的 auto-retro 思想，零配置落地。

## 复盘协议（5 分钟，不开批斗会）

对着 journal（没有 journal 就对着本次对话）回答四问，各一两句：

```text
1. 预测偏差: 哪个环节的实际难度/耗时与预期差最远？为什么判断错了？
2. 返工根因: 本次返工（如有）最早可以在哪个门被拦住？（歧义门/基线/评审/机械门）
3. 可复用打法: 这次哪个做法值得下次直接复用？（具体到操作，不写口号）
4. 项目地雷: 这个项目里踩到的、下次仍会在的坑是什么？
```

## 学习账本

有价值的答案（不是每条都有价值）写入 `.helix/learnings.md`，append-only：

```markdown
## <日期> <任务一句话> (seed-N)
- 教训: <一句话，包含触发条件——"当 X 时，先 Y"格式最有用>
- 证据: <本次的具体事例>
- 类型: 项目特定 | 通用打法
```

纪律：

- **入账门槛**：下次遇到同类情况会改变行为的才入账；"要更仔细"这类不可执行的感想不入。
- 每次 L2 任务的 clarify 阶段**回读** `.helix/learnings.md`（如果存在）——学习环只有被回读才闭合。
- 账本超过 ~30 条时做一次合并：同类教训归并，被后续经验推翻的删除（反熵同样适用于经验）。

## 向宿主记忆升级

**项目特定**教训留在 `.helix/learnings.md`（跟项目走、进 git）。**通用打法**且用户明确认可的，若宿主有持久记忆设施（如 Cindy 的 maker memory），建议用户存一份到宿主记忆——那里跨项目生效。不擅自写宿主记忆，提议由用户点头。

## 失败复盘的特别条款

代价高昂的失败（返工超过半天、破坏了用户数据/信任）复盘时追加：

- 时间线：从第一个错误信号到发现，中间隔了几步？哪个信号被忽略了？
- 拦截点：四道门（歧义/基线/评审/机械）各自为什么没拦住？
- 产出至少一条入账教训 + 一条流程修正（如"此类任务歧义门槛收紧到 0.15"——下个任务的门计算把它作为 `threshold` 参数传给 `helix_gate` 即生效；门槛只能收紧，不能放宽）。
